## 1. 核心研究问题

核心区分：**Relevance / Transferability ≠ Incremental Complementarity**。辅助信息即使与目标高度相关，也不意味着在当前 target reconstruction state 下仍有额外价值。

正式主线：

`Match → Assess → Compensate`

进一步计划加入 reconstruction-state-aware reassessment，使 `M_c^(1), M_c^(2), M_c^(3)` 随重建状态动态变化。论文动机核心问题：**“Is it relevant?” ≠ “Is it still useful?”**

## 6. P1 — S12 Proxy Incremental Assessment Proof

**定位：P1 是 proxy proof，不进入正式 M0/M1/M2/M3 消融序列。** 目的只是验证已有 cross-modal interaction 的 update 是否仍需根据 current target state 做 incremental assessment。

代码位置：`/data/ssd1/yanshuo/code2026/MTrans_CCLM_Proof`；branch=`cclm-proof`；commit=`166c669`。

核心文件：`models/cmmt_reconstruction_multi_cross_assess.py`、`config/reconstruction_multi_cross_assess.py`。Experiment=`reconstruction_multi_cross_assess`；output=`./weights_reconstruction_multi_cross_assess_random4x`；log=`train_cclm_assess_random4x_20261004.log`；tmux=`cclm_assess`。

S12 启动：

`CUDA_VISIBLE_DEVICES=0,2 python -u train.py --experiment reconstruction_multi_cross_assess 2>&1 | tee train_cclm_assess_random4x_20261004.log`

Proxy formulation：保留原 MTrans early fusion 与 CrossTransformer。保存 `x_base` 和 CrossTransformer 后的 `x_cross`；定义 `delta_x=x_cross-x_base`。Assessment relation 为 `[x_base, x_base*x_cross, abs(x_base-x_cross)]`。Assessment block 为 Conv2d(48→16,3×3)+ReLU+Conv2d(16→1,1×1)+Sigmoid。最终 `x_assess=x_base+M_c*(x_cross-x_base)`。

初始化：assessment 最后一层 weight=0，bias=2，因此初始 `M_c=sigmoid(2)=0.880797`，已实际 sanity check。

参数量：B0=783,693,410；P1=783,700,355；仅新增 6,945（约 0.000886%）。

截至 2026-10-05 最近检查：Epoch 25 正在训练；无 NaN/Inf/OOM/traceback；iteration time≈2.10s；max memory≈15003 MiB。最近完整 validation：NMSE=0.04524，PSNR=28.11 dB，SSIM=0.5863。相对 B0：+0.71 dB PSNR，+0.0597 SSIM，NMSE 相对下降约14.6%。**该结果仍是中期结果，必须跑满50 epochs并按PSNR-best规则确定最终值。**

最近 PSNR 轨迹：27.61→27.70→27.83→27.89→27.97→28.01→28.02→28.08→28.08→28.11。

当前 preliminary conclusion：incremental assessment 对 reconstruction 有强正信号，但 P1 不等价于正式 CCLM。

## 8. M1 — S12 Directional Criss-Cross Match

M1 是 Formal CCLM 的正式 Match-only baseline。它回答“Where is the corresponding auxiliary evidence?”，不回答“Is it still incrementally useful?”；后者留给 M2 Assess。

严格方向：`Q <- T`，`K,V <- A`。只更新 target representation；不执行 target→auxiliary 的信息更新，但允许 target reconstruction objective 的梯度回到 auxiliary representation。

Native-grid Criss-Cross：不把20×20 auxiliary插值到40×40。对 target `(r_t,c_t)`，映射 coarse auxiliary `(floor(r_t/2), floor(c_t/2))`，候选为该 auxiliary row 与 column 的并集，中心去重后每个 target query 恰好39个候选。因此 topology 为1600×39，而非global 1600×400。

Match dimension=256：Q `[B,1600,256]`，K/V `[B,400,256]`；对39 candidates softmax，得到 matched representation，再投影回 `[B,1600,1024]`。M1 更新为 `T' = T + F_m`，没有 `M_c`。

代码位置：`/data/ssd1/yanshuo/code2026/MTrans_CCLM_Formal`；commit=`44b55f8`。

核心组件：`models/cclm.py`；完整模型：`models/cmmt_reconstruction_directional_match.py`；Config=`config/reconstruction_directional_match.py`；Experiment=`reconstruction_directional_match`；Output=`./weights_reconstruction_directional_match_random4x`。

单元测试：candidate_index=(1600,39)，min=0，max=399，每query 39个唯一候选；forward 得到 matched_aux=(1,1600,1024)，attention=(1,1600,39)，每query attention sum≈1；完整模型 target/aux output 均为 `(1,1,320,320)`。

Gradient-flow test 仅使用 target output loss，仍得到非零 finite gradients：target_head sum_abs=1.5722e+01；auxiliary_head=2.6610e-01；match_Q=1.5223e+00；match_K=5.8894e+00；match_V=1.10215e+02；match_out=7.9890e+00；target_tail=3.0568e+00。说明 `L_target → F_m → K_A,V_A → auxiliary head` 成立。

参数量：B0=783,693,410；M1=5,908,066。M1 仅约为 B0 的0.75%，参数减少约99.25%。DirectionalCrissCrossMatch 自身=2,621,440 params（Q 262,144；K 1,048,576；V 1,048,576；out 262,144）。原 MTrans 巨大参数量主要来自 CrossTransformer。**轻量化是附加发现，不应替代 Match/Assess 的论文主故事。**

M1 当前已达到正式训练前 ready 状态，但尚未跑50 epochs。

## 9. 正式实验序列与命名

建议固定如下，避免后续混淆：

- **B0 — Original MTrans**：正式冻结基线。
- **B1 — No Early Fusion**：只删除 unconditional early addition。
- **M1 — Directional Match**：正式 Directional Criss-Cross Match，`T'=T+F_m`。
- **M2 — Match + Assess**：在 M1 上加入 incremental complementarity assessment，目标形式 `T'=T+M_c⊙F_m`。
- **M3 — Match + Assess + State**：加入 previous/current reconstruction state conditioning，跨stage重新评估互补性。
- **P1 — Proxy proof**：MTrans CrossTransformer 后的 incremental-assessment proof，只用于证明idea，不混入正式 M0–M3 消融。

当前优先级：P1继续跑满；新服务器到位后优先并行跑 B1 和 M1；拿到 B1/M1 结果后再决定 M2 的最终结构，不盲目继续堆模块。

## 10. M2 / M3 设计边界（尚未正式实现）

M2 必须明确分离 Match 与 Assess。正式关系证据计划：`R=[T, T⊙F_m, |T-F_m|]`，由轻量 assessment estimator 输出 `M_c`。M1 与 M2 的关键受控差异应尽量只有“是否评估 incremental complementarity”。

M3 才加入 reconstruction-state-aware reassessment。目标是让当前 target state 同时包含本层 target representation 与 previous cross-modal reconstruction state，然后在多个 representation levels 重复计算 Match 与 Assess。

正式方法不应继续无条件使用原 `x=x+complement`；否则在 Assess 前 auxiliary 已经被注入 target，会破坏方法逻辑。

## 11. 论文可视化与必须提前保存的中间量

这是正式实验的重要要求：**不能等论文写作阶段才补可视化。** Formal CCLM 从模型设计阶段就必须支持保存机制证据。

## 15. 当前判断与决策门槛

P1 已足以支持继续 CCLM 方向，但最终论文 claim 仍需正式 M1/M2/M3 证据链。

B1 用于判断 unconditional early fusion 的作用；M1 用于判断 structured directional correspondence 本身能做到什么。由于 M1 从783.7M降到5.9M，M1若略低于B0不能简单解释为 Match 无效；若 M1 接近或超过 B0，则是很强的附加结果。

后续最理想证据链：B1 排除 early fusion；M1 建立 correspondence；M2 明确证明 Assess 带来额外提升；M3 再证明 reconstruction-state-aware reassessment 的额外价值。

主故事始终保持：**Matching/relevance 与 incremental complementarity 是两个不同问题。** 参数效率只作为 secondary finding。

# 当前最重要的结论

1. **P1 proxy 已获得强正信号**：仅增加 6,945 参数，训练中期已从 B0 27.40 dB 提升到至少 28.11 dB；但仍需等待 50 epochs 最终结果。
2. **B1 已准备完毕**：它是隔离 unconditional early fusion 的严格 control。
3. **M1 已准备完毕**：Directional Criss-Cross Match 的 topology、forward、factory、gradient flow 均已验证；参数量仅 5.908M。
4. **正式论文主线不应变成轻量化**：参数效率是附加结果；核心仍是 `Match ≠ Assess`，以及 incremental complementarity 对 current target state 的依赖。
5. **正式 M2/M3 必须从第一天就保存机制可视化数据**，不能实验结束后再补。
